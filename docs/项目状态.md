# 项目状态

> 给下一次对话的交接文件。最后更新：2026-09-26

## 一句话

VideoToLive 是一个 macOS 应用，把视频转成 Apple Live Photo 并写入「照片」App。
卖点是**视频轨不重新编码**，输出码流与源片段逐字节一致。

- 仓库：https://github.com/xLuckww/VideoToLive （公开，MIT）
- 最新版本：v1.0.0，DMG 已发布在 Releases
- 分支：只有 `main`，本地与远端一致（`d99a94b`），工作区干净

## 当前进度

功能上已经可用，三个阶段都已完成并验证：核心管线、界面、时间轴裁剪。
界面做过一轮重新设计，改成剪辑软件式布局加淡雾蓝浅色主题。

**未开始的功能**（按优先级）：

1. 手动逐帧选择封面。核心能力已经具备（`CoverFrameExtractor.extract` 支持帧精确定位，
   `vtl frames` 可验证），缺的是界面：逐帧步进、缩略图条、显示当前帧清晰度评分。
2. 批量队列。需要队列列表、逐个状态显示、暂停取消，并发数限制在 2–3，避免 4K 素材吃爆内存。
3. 偏好设置。封面格式与质量、是否保留音轨、默认裁剪时长、是否自动打开照片 App。
   这些参数核心库和命令行都支持了，只是界面没有暴露。

原始需求见 [开发方案](../LivePhotoForge-开发方案.md) 第 4.3、4.5、4.6 节。

## 不能破坏的技术约定

这几条一旦改错，功能会**静默失效**——不报错，但产出的文件不是合格的 Live Photo。

1. **passthrough 的两个 nil。** `AVAssetReader` 与 `AVAssetWriter` 两端的 `outputSettings`
   都必须是 `nil`，只要有一端不是，就会走重新编码。见 `LivePhotoVideoWriter.remux`。
2. **不要用 `AVAssetExportSession`。** 它无法写入自定义定时元数据轨，这正是其他同类工具
   只能退回重新编码的原因。
3. **配对三要素缺一不可。** 静态图 Maker Note 键 `17`、MOV 的 `content.identifier`、
   MOV 的 `still-image-time` 定时元数据轨，三者用同一个 UUID。第三条最容易漏，
   漏了之后照片 App 可能仍识别为实况，但长按播放时的静止画面位置不对。
4. **抽帧容差必须显式设为 `.zero`。** 否则会拿到邻近帧，表现为「按方向键画面不变」。
5. **吸附只在编排层算一次。** `LivePhotoConverter.convert` 算出区间后，封面挑选和视频封装
   共用同一个区间。之前两边各算各的，导致封面帧落在成品之外。那里留了一条不变式断言，
   封面帧不在成品区间内会直接报错，不要删掉。

## 环境限制

这些是踩过的坑，换台机器或换人接手会再遇到。

1. **没有安装完整 Xcode，只有 Command Line Tools。** 所以 SwiftUI 的 `@State`、`@FocusState`
   这类宏**不能用**，它们的宏插件只随完整 Xcode 分发。现有代码把所有界面状态都放在
   `AppModel` 里绕开了这个限制，包括拖拽过程中的临时值。继续写界面时要沿用这个写法，
   或者装完整 Xcode。
2. **macOS 文件系统默认不区分大小写。** 命令行工具叫 `vtl` 而不是 `videotolive`，
   就是因为后者会和 App 目标 `VideoToLive` 的源码目录、编译产物冲突。
3. **App 是 ad-hoc 签名，没有经过 Apple 公证。** 用户第一次打开需要手动允许。
   签名变化会导致照片图库权限需要重新授权。
4. **`gh` 命令行当前认证已失效**（返回 401）。需要推送或操作 Releases 时，
   先运行 `gh auth login`。普通 `git push` 和 `git fetch` 目前仍然可用。

## 怎么验证改动没有破坏无损

改完核心库后，跑这三步：

```bash
swift build -c release

# 1. 转换一段测试素材
.build/release/vtl convert 视频.mov --start 11 --duration 5 --cover auto --out ./out --no-import

# 2. 检查配对三要素，应当看到 4 个 ✅
.build/release/vtl verify out/*/*.mov out/*/*.heic

# 3. 比对码流，两行 MD5 必须相同
ffmpeg -v error -ss 10 -t 5 -i 视频.mov -map 0:v:0 -c copy -f md5 -
ffmpeg -v error -i out/*/*.mov -map 0:v:0 -c copy -f md5 -
```

注意第 3 步的起点要用**吸附后**的实际起点，转换结果里会打印出来。

测试素材可以用 ffmpeg 现造：

```bash
ffmpeg -f lavfi -i "testsrc2=size=3840x2160:rate=30:duration=20" \
  -f lavfi -i "sine=frequency=440:duration=20" \
  -c:v hevc_videotoolbox -b:v 40M -tag:v hvc1 -g 60 -pix_fmt yuv420p \
  -c:a aac -shortest testdata/4k_hevc.mov
```
